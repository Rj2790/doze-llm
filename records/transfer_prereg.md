# Transfer to new rules — pre-analysis note (drafted 2026-09-12, NOT launched)

Question from the user: do the trained adapters figure out *different* rules
faster, or perform better on them, than the base model? Written before any
run; to be revised once the follow-up (A/B/C) results are in, because they
decide the controls this needs.

## Two different questions

1. **Zero-shot transfer.** Evaluate base + the 13 adapters on new puzzles
   with a different rule, no further training. Measures whether what was
   learned (digit tracking, format compliance) generalises. Prediction from
   the current analysis: adapters beat base on same-shape puzzles (12 digits,
   left-to-right fold) with a *permuted* table, because tracking transfers;
   smaller or no advantage when the shape changes.
2. **Learning-to-learn.** Run the Online regime (the cheapest, best-behaved
   trained arm) on the new rule from two starting points: base, and an
   Online adapter from the old rule. Compare day-accuracy and held-out curves
   over 300 episodes. Control for format familiarity by giving the base
   start an equal number of steps on *format-only* examples (old rule, but
   the model only ever sees the output format) — otherwise "faster" just
   means "already knows the format".

## The outcome to watch: negative transfer

600 steps entrenched one mapping (e.g. 1,4 -> 9). If the new table says
1,4 -> 1, an adapter may keep emitting the old value. Measure the fraction of
wrong steps whose output equals the *old* table's output; if it exceeds the
1/2 chance level for a wrong digit, the adapter is applying the old rule.
This is the most informative single number in the design.

## Rule variants (all generated by parametrising `tasks/number_reduction.combine`)

- V1 permuted table: same alphabet {1,4,9}, same "same->same", but
  different->the *smaller* of the two (breaks the "third digit" rule).
- V2 four symbols {1,4,7,9}: different->the symbol not among the two with the
  lowest value (needs a genuinely new lookup).
- V3 right-to-left fold with the original table (changes tracking direction,
  keeps the table).

Splits: prefix-disjoint as before; no mirror structure is imposed (no hidden
shortcut; this is a transfer study, not an insight study). Held-out 201 items
per variant.

## Measures and controls

- Full-chain accuracy (work format), per-step error position, old-rule
  error fraction, tokens per attempt (length control from the start).
- Zero-shot: 14 models × 3 variants × 201 items ≈ 8,400 generations ≈ 1 GPU-h
  on L4.
- Learning-to-learn: V1 only, 3 seeds × 2 starting points (+1 format-control
  start) × 300 episodes Online ≈ 9 runs × ~1.2 h on L4 ≈ 11 GPU-h.

## Decision rules

- Zero-shot: adapter − base ≥ +0.10 on V3 and ≈ 0 on V1/V2 → what
  transferred is tracking, not rule knowledge. Adapter − base ≤ −0.10 on V1
  with old-rule error fraction > 0.5 → negative transfer (entrenchment).
- Learning-to-learn: adapter start reaches 0.80 held-out ≥ 100 episodes
  earlier than the *format-controlled* base start → learning-to-learn
  beyond format; earlier only than the naive base start → format effect.

## Not to run until

A/B/C results are in (if C shows no generalisation to unstructured strings,
transfer to new rules is moot) and the user says go.
